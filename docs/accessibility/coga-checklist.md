# ELDERCARE 360: W3C COGA Cognitive Accessibility Conformance Checklist

**Reference:** W3C Making Content Usable for People with Cognitive and Learning Disabilities (COGA).

| COGA Objective | Guidance & Requirement | ELDERCARE 360 Implementation | Conformance Status |
| :--- | :--- | :--- | :--- |
| **Objective 1: Help users understand what things are and how to use them** | Clear affordances, familiar icons paired with text labels, no hidden gestures as sole paths. | Every icon is paired with visible text ("Due Now", "Taken"). Hold-to-confirm has plain tap alternative. | **PASS** |
| **Objective 2: Help users find what they need** | Predictable layout, single primary action per elder screen, clear current location. | One primary action on Elder Home (Day Ring / Next Dose). Maximum 5 choices per elder screen. | **PASS** |
| **Objective 3: Use clear content (text and images)** | Plain language, short sentences ($\le 12$ words), everyday words, no clinical jargon. | Elder copy uses simple words ("medicine", not "medication"; "doctor visit", not "encounter"). | **PASS** |
| **Objective 4: Help users avoid mistakes and recover easily** | Forgiveness, undo on destructive or critical actions, clear review steps. | 10-minute visible countdown undo for doses; 24-hour undo on timing edits. | **PASS** |
| **Objective 5: Help users focus** | Chunk information, generous whitespace, no auto-advancing carousels or flashing items. | Calm Clarity aesthetic; high white space; reduced motion mode suppresses all non-essential animation. | **PASS** |
| **Objective 6: Ensure processes do not rely on memory** | Avoid requiring users to recall numbers or instructions across screens. | Dose cards display pill color, dosage, timing, and meal instructions directly. | **PASS** |
| **Objective 7: Provide adaptation and personalization** | User comfort settings (text size, contrast, spacing, audio read-aloud). | Flagship Comfort Profile: 5 text scales (up to 200%), High Contrast, Read Screen Aloud. | **PASS** |
| **Objective 8: Support users when things go wrong** | Plain-language error messages explaining what happened, what it means, and what to do next. | Error messages follow strict 3-part structure without error codes or blame. | **PASS** |
